Start here

CALL-E makes the phone call. This repo decides what the call means for the business.

A fictional Mexican lender, Financiera Solaria, wants an AI agent to remind customers of an upcoming installment and record the outcome in its CRM. CALL-E (by AI Rudder) does the phone part: it dials, holds the conversation in Spanish and returns a structured result. This repo is the glue. It decides who to call, tells CALL-E what to do, checks the result, and writes a status and a follow-up task into the CRM.

The product

What CALL-E is

For a person (the website)

At heycall-e.com you describe a goal in plain language ("call this number and confirm Friday's appointment") and give a phone number. CALL-E plans the call and asks about any missing details before dialing. It then holds the conversation and gives you a summary, transcript and structured result.

For a developer (what this repo uses)

  • Developer API / SDK: POST /v1/calls with a task, recipients, a result_schema, metadata and a webhook URL. GET /v1/calls/{id} reads the result.
  • MCP / agent plugins: plan_call → run_call → get_call_run, used from Claude Code, Cursor and similar tools.
  • Webhooks fire on call.completed, call.failed and call.result_validation_failed. They are unsigned.

Goal-driven, not scripted

You don't draw a dialogue tree. You write the goal and rules (the "task") and the shape of the answer you need (the "schema"). CALL-E handles the conversation, including voicemail, IVR menus and interruptions.

Mexico

Supported (MX, Spanish and English) but through an international line, which CALL-E describes as mainly for development and testing. A real pilot needs a local number or a SIP trunk.

Your checklist

What to do in the CALL-E dashboard

  1. Create an account at heycall-e.com. New accounts get 100 free credits (about US$1).
  2. Optional, to explore the product: place one call to your own phone from the CALL-E web app by typing a goal and your number. This is the "customer experience" the assignment asks you to explore.
  3. Create an API key: dashboard.heycall-e.com/account/api-keys. Copy it.
  4. Paste it in this app: Control center → Call my phone → step 1. Or put CALLE_API_KEY=... in .env and restart.
  5. Enter your phone and press Call me now. Answer, and play the customer using one of the scripts.
  6. Afterwards, check usage under dashboard → billing.

These steps follow CALL-E's public README; the dashboard's exact labels may differ. Only countries on CALL-E's supported list can be called (US, CA, MX, ES, BR, GB, DE, IN, and others). The selector on the "Call my phone" tab lists them.

Responsibility

Who decides what

Instructions (prompt)

What the agent says: AI disclosure, confirming it's the right person, the reminder, clarifying once, handling exceptions, and things it must never do. File: agent_config.build_task. Shown in each call's "Request sent to CALL-E".

Workflow config (schema)

The shape of the answer: enum outcomes with unknown, an ISO date, how certain the promise was, the evidence quote. Also region/locale, metadata and the idempotency key. File: agent_config.RESULT_SCHEMA.

External logic (code)

Who may be called and when (guards.py). What an answer means: status, task, team, priority (outcomes.py). A promise only counts if it's specific, firm, and at most 7 days after the due date.

Terminal

Doing the same from the terminal

Every button calls a JSON endpoint, so you can do everything with curl. Paste one line at a time in zsh.

./setup.sh                          once: venv + dependencies + tests
./run.sh                            start CRM :8001 + orchestrator :8000 (Ctrl+C stops)
./demo.sh                           narrated terminal demo (starts services if needed)
.venv/bin/python -m pytest -v       run all tests

curl localhost:8000/api/status
curl -X POST localhost:8000/api/reset
curl -X POST localhost:8000/api/campaign -H 'content-type: application/json' -d '{}'
curl localhost:8000/calls
curl localhost:8001/accounts/ACC-1001
curl localhost:8001/tasks
curl -X POST localhost:8000/api/simulate -H 'content-type: application/json' -d '{"scenario":"human_requested"}'
curl -X POST localhost:8000/api/outage-scenario
curl -X POST localhost:8000/api/crm/restore-and-retry
curl localhost:8000/api/calls/CALL_ID/detail
curl -X POST localhost:8000/calls/CALL_ID/sync
curl localhost:8000/api/troubleshoot
curl localhost:8000/agent-config                       the result schema sent to CALL-E

Full, interactive API reference: localhost:8000/docs and localhost:8001/docs. You can try every endpoint from the browser there.
